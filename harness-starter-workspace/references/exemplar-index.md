## 매칭 규칙 (Planner가 사용)

1. 사용자 1문장 → 상위 키워드 추출
2. 카테고리 1~10 중 가장 가까운 번호 확정
3. 카테고리 내 exemplar 후보 1~3개 제시
4. 사용자가 선택 → `selected_exemplar` 확정
5. 매칭 실패(유사도 < 0.5) → 가장 가까운 exemplar 기반 **변형 모드** 또는 사용자에 재확인

## exemplar 구조 (복제 단위)

```
{NN}-{harness-name}/.claude/
├── CLAUDE.md                  — 프로젝트 개요
├── agents/
│   ├── {specialist-1}.md      — 도메인 전문가
│   ├── {specialist-2}.md
│   ├── {specialist-3}.md
│   ├── {specialist-4}.md
│   └── {reviewer}.md          — 교차검증자 (필수)
└── skills/
    ├── {orchestrator}/skill.md
    └── {agent-extending}/skill.md
```

## 치환 대상 (Generator가 사용)

| 원본 요소 | 치환 내용 |
|---------|---------|
| 하네스 이름 (NN-name) | 사용자 프로젝트명 |
| 도메인 용어 (YouTube, 계약서 등) | 사용자 도메인 용어 |
| 트리거 키워드 | 사용자 도메인 키워드 |
| `_workspace/` 산출물 파일명 | 유지 (번호 컨벤션) |
| agents/ 구성 | 유지 (역할명만 필요시 치환) |
| skills/ 프레임워크 | 유지 (Porter's·IRAC·Bloom's 등 도메인 표준) |
