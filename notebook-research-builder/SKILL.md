# notebook-research-builder — 노트북을 원천으로 2차 산출물 만들기

## 노트북 단일 원천 원칙 (이 스킬의 목적 — 모든 단계보다 우선)
1. **모든 지식은 노트북으로.** 웹검색·크롬·어사이드·리서치는 지식을 **찾아 노트북에 넣는 일**만 한다. 검색 요약문·에이전트 자신의 지식은 산출물에 쓰지 않는다.
2. **모든 산출물은 노트북에서.** 본문의 모든 문장은 노트북 질의(`nrb.py query`)의 답·인용에서 온다. 에이전트는 구조·톤·서술방식만 바꾼다.
3. **추가 지식도 같은 길로.** 추천 → 검색 → 주입 → 재질의 → 작성. 넣기 전에는 한 글자도 쓰지 않는다.
4. **로컬 폴더는 기록일 뿐.** `sources.jsonl`·`queries/`·`draft/`는 재개·추적용이지 원천이 아니다.
5. **파생 지식은 소스로 되먹이지 않는다.** 질의 결과는 노트(note)로만 둔다(원천·파생이 섞여 자기강화되는 것 방지).
6. 한 노트북은 **여러 관점 산출물의 원천**으로 재사용한다(`state.json`의 notebook_id).

## 진행 방식
- 시작·재개는 항상 `uv run <스킬>/scripts/nrb.py status -P <프로젝트>` — 된 단계는 건너뛴다. 새 작업이면 0단계부터.
- **한 번에 하나만 묻고**, 매번 ①왜 필요한지 한 줄 ②추천값 ③「Enter면 추천대로」.
- 수집·주입·질의는 **사람 개입 없이** 진행하고 단계마다 한 줄 보고. 사람 몫: 로그인·캡차·4개 게이트·한도 도달 판단.
- 토큰·쿠키·비밀번호는 다루지 않는다. 삭제(소스·노트북)는 항상 먼저 묻는다.

## 0. 준비 — 설치가 기본 · [references/setup.md](references/setup.md)
1. **설치기 먼저**: `bash <스킬>/scripts/install.sh` (Windows: `install.ps1`) — 이 PC를 탐색해 없는 것은 설치하고, 있는 것은 「이미 설치됨 — 건너뜀」. 「남은 할 일」(사람 차례: 구글 로그인·브라우저 확장·앱 로그인·관리자 암호)은 하나씩 안내하고 끝나면 다시 실행 → 남은 할 일이 없을 때까지. 설치하지 않고 다른 길로 가는 건 **사용자가 고를 때만**(`--skip`).
2. 작업 셸 환경: `eval "$(uv run <스킬>/scripts/nrb.py env)"` — 이후 모든 스크립트는 `uv run`으로(파이썬 버전 무관).
3. `nrb.py tier`로 **요금제 감지 후 무료/유료 소스 한도를 설명**(무료 약 50 · 유료 약 300, 유료 전환은 사용자 판단).

## 1. 산출물 유형·입력
1. 「무엇을 만드나요?」 → 프리셋 선택: [교안](references/presets/courseware.md) · [시장조사](references/presets/market-research.md) · [트렌드](references/presets/trend.md) · [논문 리뷰](references/presets/paper-review.md) · 기타(가장 가까운 프리셋 + 자유 항목)
2. 프리셋의 「입력」 항목을 한 칸씩: 목표(구현 방향이 적힌 기술구현 목표 등)·키워드·사용자 관련 문서(파일·URL)
3. `nrb.py init --title "<주제>" --preset <프리셋>` → 실행한 폴더 아래 `<날짜>_<주제>/` + 새 노트북. 기존 노트북을 원천으로 쓰면 `--notebook-id`.
4. 사용자 문서를 **가장 먼저** 넣는다: `nrb.py add -P <프로젝트> --file <문서> --via user` / `--url <URL> --via user`

## 2. 검색 범위 — 한 칸씩 추천하고 묻기
- 기간: 「게시 날짜 기준을 어디까지 할까요? 추천: <프리셋 추천값>」 (예: 최근 3개월)
- 주요 사이트: 「주로 어디서 찾을까요? 추천: <프리셋 추천 사이트>」 (예: 유튜브·스레드) → 총 소스의 **60% 이상**을 이 범위·기간에서
- 수집 개수 목표(한도 고려)와 키워드 변형 목록을 짠다 → `nrb.py scope -P … --since <YYYY-MM-DD> --sites youtube,threads --ratio 0.6`
- **게이트 ①** 검색계획 승인 → `nrb.py gate -P … 1` · [references/gates.md](references/gates.md)

## 3. 수집·주입 (혼합, 자동) — [references/collect.md](references/collect.md)
- 주요 사이트·기간 몫(≥60%): 에이전트가 찾고 **게시일을 페이지에서 확인**한 뒤 주입. 공개 페이지·유튜브는 URL로, **로그인 벽(스레드·인스타 등)은 크롬→어사이드 순으로 본문을 추출해 텍스트로**(날짜 머리말 자동).
- 나머지: `nlm research`로 후보를 받아 → 관련성·날짜 확인 → 골라서 import → `nrb.py date`로 게시일 등록.
- 실패는 자동 대체(URL 실패 → 텍스트 추출 → 건너뛰고 기록). 수시로 `nrb.py ratio`.
- **게이트 ②** 소스 목록·비율 보고. 미달이면 ①기간 넓히기 ②사이트 추가 ③이대로 진행 중 선택.

## 4. 커버리지 질의 — [references/query-write.md](references/query-write.md)
프리셋의 「커버리지 질의」로 관련 기술·쟁점이 빠짐없이 걸리게 여러 번 질의 → `nrb.py query … --note`(노트로 저장). 질의에서 드러난 빈 곳은 3단계로 돌아가 채운다.

## 5. 설계 인터뷰 → 목차
프리셋의 「설계 인터뷰」를 한 칸씩(교안: 목표·수강자 수준·톤앤매너·서술방식·분량) → 노트북 질의로 목차 초안 → **게이트 ③** 목차 승인.

## 6. 섹션별 작성 + 추가 지식 루프 — [references/query-write.md](references/query-write.md)
섹션마다 질의 → 답·인용으로 `draft/<섹션>.md` 작성(인용 `[qNN:n]` 유지) → `nrb.py check`로 인용 없는 문장 0 확인.
섹션 사이에서 빈 곳·최신 사례를 **추천하고 묻는다** → 고르면 3단계 방식으로 주입 → 재질의 → 반영.
**게이트 ④** 초안 검토 + 출력 형식 선택.

## 7. 출력 — [references/output.md](references/output.md)
먼저 `nrb.py export`로 각주판(md·html)을 만든다 → 워드(docx 스킬) · 파워포인트(pptx 스킬) — 둘 다 설치기가 깐 anthropics/skills · 웹(export html, 에이전트에 게시 도구가 있으면 게시) · NotebookLM Studio(오디오·영상·퀴즈·플래시카드·마인드맵·슬라이드·인포그래픽 — 노트북에서 바로 생성, `NOTEBOOKLM_HL=ko`). 결과물은 `output/`.

## 끝나고 보고할 것
프로젝트 폴더 · 노트북 링크 · 소스 수(기간·주요 사이트 비율) · 질의 수 · `check` 결과(인용 없는 문장 0) · 산출물 경로 · 해 보지 못한 것. 같은 노트북으로 만들 수 있는 **다른 관점 산출물**을 1~2개 제안.
