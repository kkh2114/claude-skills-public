# 게이트 4개 + 원칙 점검

각 게이트에서 보여 주고 사용자 답을 받은 뒤 `nrb.py gate -P <프로젝트> <번호> --note "<결정 요약>"`.
매 게이트마다 아래 **원칙 점검 3줄**을 같이 보고한다.

| 게이트 | 보여줄 것 | 받을 답 |
|---|---|---|
| ① 검색계획 | 프리셋·목표·키워드 변형 목록·기간·주요 사이트·목표 비율·수집 개수(한도 대비)·추출기(크롬/어사이드) | 승인 / 수정 |
| ② 수집 결과 | `nrb.py ratio` 결과 + 실패·건너뜀·빈 소스 목록 | 진행 / 기간 넓히기 / 사이트 추가 / 빈 소스 삭제 승인 |
| ③ 목차 | 목차 + 장별 근거 소스 수 + 커버리지 질의에서 드러난 빈 곳 | 승인 / 수정 / 보강 주제 |
| ④ 초안 | 섹션별 분량·`check` 결과·인용 소스 수 | 출력 형식(복수) |

## 원칙 점검 (매 게이트)
1. **넣지 않은 출처가 쓰였나?** — 검색 요약·에이전트 지식이 초안/계획에 들어갔으면 ✗
2. **인용 없는 문장이 있나?** — `nrb.py check` ✗ 개수 (게이트 ③ 이후)
3. **로컬 파일이 원천으로 쓰였나?** — `inbox/` 본문을 노트북에 넣지 않고 바로 인용했으면 ✗
하나라도 ✗면 고친 뒤 다음으로.

## 사람 몫 (게이트 밖에서 멈추는 경우)
로그인·캡차 · 소스 한도 도달(뺄 소스 선택/유료 전환) · 소스·노트북 삭제 · 시네마틱 영상 등 쿼터 큰 생성.
