# 4·6. 질의 → 작성 (노트북의 소스 내 지식만)

## 질의 도구
```bash
uv run <스킬>/scripts/nrb.py query -P <프로젝트> --name <짧은이름> --q "<질문>" [--note] [--source-ids a,b]
```
- 결과: `queries/NN-<이름>.json`(답·인용 번호→소스 ID·인용 원문) + `.md`(인용 → 소스 제목). `--note`면 노트북 노트로도 저장(소스로는 넣지 않음).
- 질문 끝에 항상 「각 주장마다 출처를 밝혀줘」 — 인용 없는 답은 쓰지 않는다.
- 특정 소스 묶음만 보고 싶으면 `--source-ids`(예: 최근 3개월 소스만으로 「최신 동향」 섹션).

## 4. 커버리지 질의 (프리셋의 질의 목록 + 아래 공통)
목표를 이루는 데 필요한 **관련 기술·개념·쟁점이 빠짐없이 걸리게** 각도를 바꿔 여러 번 묻는다:
1. 「<목표>를 구현하려면 필요한 기술·도구·개념을 빠짐없이 나열하고 각각 무엇을 하는지」
2. 「소스들이 서로 다르게 말하는 지점(의견 차·버전 차)」
3. 「최근(<since> 이후) 새로 등장하거나 바뀐 것」
4. 「초보자가 가장 많이 막히는 지점과 해결」
5. 「실제 사례·수치·코드 예」
6. 「이 소스들로 답할 수 없는 것 — 빠진 주제」 ← **빈 곳 찾기: 여기 나온 것은 3단계로 돌아가 채운다**
- 각 답은 `--note`로 저장. 답에서 소스가 한두 개에만 몰리면 그 주제의 소스를 더 넣는다.

## 5. 목차 만들기
설계 인터뷰 답(목표·수준·톤·서술방식·분량)을 넣어 질의: 「<인터뷰 요약>에 맞춰 이 소스들로 가르칠 수 있는 목차를 만들어줘. 각 장에 근거 소스를 달아줘」 → 근거 소스가 없는 장은 빼거나 3단계로. → 게이트 ③.

## 6. 섹션별 작성 규칙
1. 섹션마다 질의 1~3번(개념 설명 / 예시·사례 / 실습·퀴즈 재료). 질문에 수준·톤·서술방식을 넣는다.
2. `draft/NN-<섹션>.md`에 쓴다. **NotebookLM 답의 `[n]` → `[qNN:n]`으로 바꿔 그대로 유지**. 한 문장에 여러 근거면 `[q03:2][q05:1]`.
3. 에이전트가 할 수 있는 것: 순서 바꾸기, 문장 다듬기, 수준에 맞게 쉽게 풀기, 표·목록으로 바꾸기, 연결 문장. **할 수 없는 것: 노트북에 없는 사실·수치·예시 추가.** 필요하면 질의를 더 한다.
4. 출처가 필요 없는 줄(학습목표 문구, 섹션 안내, 활동 지시)은 줄 앞에 `[출처 불필요]`.
5. 섹션을 마칠 때마다:
```bash
uv run <스킬>/scripts/nrb.py check -P <프로젝트> --draft <프로젝트>/draft/NN-<섹션>.md
```
   ✗가 0이 될 때까지 고친다(근거를 질의로 찾거나 문장을 지운다). `draft/refs.md`가 참고 소스 목록이 된다.

## 추가 지식 루프 (섹션 사이)
- 쓰면서 보인 빈 곳·약한 근거·더 최신 사례를 **2~3개 추천**: 「<주제>를 보강하면 <이유>. 찾아서 넣을까요?」
- 고르면 → collect.md 방식으로 검색·주입 → 그 주제로 재질의 → 해당 섹션 수정 → check.
- 고르지 않으면 넘어간다(추천을 강요하지 않음).

## 게이트 ④ 보여줄 것
목차와 섹션별 분량, `check` 결과(전 섹션 ✓), 인용 소스 수/노트북 소스 수, 출력 형식 질문(워드·PPT·웹·Studio — 복수 가능).
